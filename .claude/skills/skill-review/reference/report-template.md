# レビュー レポート テンプレート

レビュー結果はこの統一様式で出力する。指摘と改善提案は1つにまとめ、カテゴリ毎に
セクション分けして**表形式**で示す。末尾に推奨ネクストアクションを1つ提示する。

## 重大度の定義

| 重大度 | 意味 | 例 |
| --- | --- | --- |
| **Critical** | 発見・動作を阻害する。優先的に修正が必要。 | description が一人称、`name` が規約違反、`metadata.author` 欠落 |
| **Warning** | 品質を明確に下げる。修正が望ましい。 | SKILL.md が500行超、参照が2階層、Windows形式パス、時限情報 |
| **Suggestion** | 改善余地。任意対応。 | 冗長な説明、用語の不統一、目次の欠如、抽象的な例 |

---

## 出力テンプレート

以下の構成でレポートを出力する。

```markdown
# Skill レビュー: <name>

## 対象概要
- name: <name>
- path: <skill ディレクトリのパス>
- 構成ファイルと行数: SKILL.md (NNN 行) / reference/xxx.md (NNN 行) ...

## スコアサマリ

| 観点 | 判定 | 主な指摘 |
| --- | --- | --- |
| Frontmatter 検証 | ✅ / ⚠️ / ❌ | （ひとこと） |
| 簡潔さ | ✅ / ⚠️ / ❌ | |
| 指示の具体度（Degrees of freedom） | ✅ / ⚠️ / ❌ | |
| スキルの構造 | ✅ / ⚠️ / ❌ | |
| 命名規約 | ✅ / ⚠️ / ❌ | |
| 一貫性・時限情報 | ✅ / ⚠️ / ❌ | |
| ワークフロー | ✅ / ⚠️ / ❌ | |
| 例示 | ✅ / ⚠️ / ❌ | |
| スクリプト品質 | ✅ / ⚠️ / ❌ / N/A | |

判定凡例: ✅ 問題なし / ⚠️ Warning または Suggestion あり / ❌ Critical あり

## 指摘＆改善提案

問題が見つかったカテゴリのみセクションを設ける。各セクションは表形式で示し、
「推奨修正」列には具体的な修正内容（必要なら修正後の文面）を記載する。

### Frontmatter 検証

| 重大度 | 該当箇所 | 問題 | 推奨修正 |
| --- | --- | --- | --- |
| Critical | SKILL.md frontmatter | `description` が一人称（"あなたは…使えます"） | 三人称に変更: 「〜をレビューする。〜のときに使用する」 |

### スキルの構造

| 重大度 | 該当箇所 | 問題 | 推奨修正 |
| --- | --- | --- | --- |
| Warning | SKILL.md (612 行) | 本文が500行制限を超過 | 「API詳細」節を reference/api.md に分離し、リンクで参照 |

（以降、該当カテゴリごとに同様の表を続ける）

## 推奨ネクストアクション

最優先で着手すべきアクションを **1つだけ** 提案する。例:
「まずは、スキルの発見精度に直結する `description` を三人称に書き直すところから始めてみましょうか？」
```

---

## 記入のポイント

- **該当箇所**は可能な限り具体的に（ファイル名・行・節見出し）。
- **推奨修正**は実行可能な粒度で。文面修正なら修正後テキストを示す。
- 問題のないカテゴリは「指摘＆改善提案」のセクションを省略し、スコアサマリで
  ✅ とする。
- 推奨ネクストアクションは Critical があればその解消を、なければ最も効果の高い
  改善を1つ選ぶ。複数並べない。
