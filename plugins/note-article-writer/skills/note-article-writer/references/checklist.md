# 公開前セルフチェックリスト

原稿をArtifactとして出力する前に、上から順に点検する。引っかかった箇所はその場で直してから出力する。

## A. スタイル要件（分析屋ブログの絶対ルール）

- [ ] **1段落が1〜3文に収まっている**。4文以上の段落があれば分割する。
- [ ] **全文がですます調**である。だ・である調が混ざっていない。
- [ ] トーンが**丁寧かつ真面目**である。軽すぎる口語・くだけたノリになっていない。
- [ ] **太字が0〜3か所**に収まっている。多ければ、本当に効かせたい1〜2か所だけ残して削る。
- [ ] 見出しやリスト項目の頭を機械的に太字にしていない。
- [ ] **比喩・たとえ話**を使っていない。具体的な事実・事例で語っている。

## B. AIっぽさの除去（詳細は ai-tells.md）

- [ ] 文末が単調に連続していない（「〜です。〜ます。」の繰り返しがない）。
- [ ] 「サポート」「提供」「最適化」「実現」「本質的」などの抽象語で押し切っていない。
- [ ] 「結論から言うと」「本記事では〜解説します」などの過剰な前置きがない。
- [ ] 「一般的に」「状況によって異なりますが」などの安全クッションを多用していない。
- [ ] 接続詞（また・さらに・そのため）が各段落頭に機械的に並んでいない。
- [ ] 「いかがでしたか」などの空虚な締めの定型句がない。

## C. 内容の価値（E-E-A-T）

- [ ] **一次情報が記事の核になっている**。実案件の知見・現場の判断・PoCの気づき・社内の取り組みなど、ネットにもAIにもない情報が中心にある。
- [ ] 一般論の寄せ集めで終わっていない。「では実際にどうだったか」が書かれている。
- [ ] 可能な箇所で具体（数値・固有の状況・実際にとった選択）が入っている。

## D. 事実関係（ファクトチェック）

- [ ] 統計・数値・固有名詞・法律・制度・他社事例を、根拠なく書いていない。
- [ ] **ユーザーが提供していない数字・事例・固有名詞を創作していない**。
- [ ] 「弊社では〜」といった体験談を捏造していない。
- [ ] 公開前に裏取りが必要な箇所が残る場合、それを原稿出力時にユーザーへ明示する準備ができている。

## E. 構成・タイトル

- [ ] タイトルが40文字以内を目安に収まり、中身と一致している（誇張・タイトル詐欺がない）。
- [ ] リード文で「誰のどんな関心に応える記事か」「読むメリット」が伝わる。
- [ ] 結論・要点が記事の前方に置かれている。
- [ ] 見出しだけ読んでも記事の流れが追える。

## 出力時の振る舞い

- 記事原稿はMarkdownファイルとして出力する。
- 出力後の会話文は短く。原稿を会話に再掲しない。
- ファクトチェックが必要な箇所があれば、その一覧だけ簡潔に伝える。
