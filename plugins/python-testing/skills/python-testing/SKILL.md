# Python Testing

## テストの実装手順

### 1. 前提条件の確認

* `README.md`やドキュメントフォルダなどを探索し、テスト対象のシステムの要件を把握します。
* フォルダ構造も確認し、プロジェクト全体のアーキテクチャを把握します。

※この時点では、実装の詳細な理解は不要です。テスト対象のシステムの大まかな要件を把握することが目的です。

### 2. テスト要件のヒアリング・確定

テストを実装する前に、ユーザからテスト要件をヒアリングし、テストに関する要件を確定させます。

最低限確定させる項目:
* テストに使用するフレームワーク（pytest、unittestなど）
* テストの種類（単体テスト、結合テストなど）
* テスト対象のスコープ
* カバレッジ目標

※既にこれらの要件が確定している場合は、ヒアリングは不要です。

### 3. テスト環境の準備

テストを実行するための環境を整えます。具体的には以下の作業を行います。
* 必要なライブラリのインストール（例: `pytest`, `pytest-cov`）
* テスト用の設定ファイルの作成
* テストデータの準備

### 4. テストコードの作成

要件が確定したら、テストコードを作成していきます。

要件定義書や仕様書が存在する場合は、それに基づいてテストケースを設計します。
この時、「既存の実装がエラー無く動作するか」をテストするのではなく、「仕様通りに動作しているか」を確認することを意識してテストコードを作成します。
また、コードコメントやdocstringにおいて、対応する要件番号や仕様番号を明記することで、テストコードと要件の対応関係を明確にします。

### 5. テストの実行

テストコードを作成したら、実際にテストを実行します。

テストが失敗した場合、以下のフローに従って対応します。

1. 失敗したテストケースの原因を特定する
2. 実装に問題がある場合は、実装側のコードを修正する
3. テストコード側に問題がある場合は、テストコードを修正する
4. 仕様自体に問題がある可能性がある場合は、ユーザに確認し、必要に応じて仕様と実装を修正する
5. 修正後、再度テストを実行し、すべてのテストが成功することを確認する
6. 最後にカバレッジを確認し、目標カバレッジに達していない場合は、追加のテストケースを作成し、再度テストを実行する

この時も、安直にテストコードを修正するのではなく、仕様通りに動作しているかを確認することを意識します。

### 6. テスト結果の報告

テストが完了したら、テスト結果を `<project_root>/tests/test_results/<YYYYMMDD_HHMMSS>.md` の形式で保存し、ユーザに報告します。

レポートのフォーマットは `references/report-template.md` を使用してください。

## ディレクトリ構造

ディレクトリ構造は、他の場所で指示がない限り、以下のようにしてください。

```
<project_root>/
└── tests/
    ├── unit/         # 単体テスト
    ├── integration/  # 結合テスト
    ├── testdata/     # テストデータ
    ├── test_results/ # テスト結果
    └── conftest.py   # pytestの設定ファイル
```

## ベストプラクティス

* テスト関数の名前は説明的な名前を使用する。
  - 良い例: `test_addition_of_two_numbers`
  - 悪い例: `test_func1`
* エッジケース（空入力、None値、境界条件など）をテストする。
* テストコードはコンパクトで読みやすく保つ（例: パラメータ化テストを活用する）。
* モックの使用は必要最小限に留める。モックの使用が複雑になると、テストコードの可読性が低下する。

## アンチパターン

| アンチパターン | 影響 | 対策 |
|----------------|------|------|
| 仕様ではなく、単に「既存の実装がエラー無く動作するか」をテストしてしまう。 | 仕様と実装が乖離している場合にもテストが通ってしまい、バグを見逃す可能性がある。 | 仕様に基づいたテストケースを設計する。 |
| サードパーティの内容をテストしてしまう。 | サードパーティのコードにバグがあった場合、テストが失敗してしまい、テストの運用が困難になる。 | サードパーティのコードは信頼し、必要に応じてモックを使用する。 |
| テストで例外をキャッチしてしまい、テストが失敗しないようにしてしまう。 | 例外が発生してもテストが失敗しないため、バグを見逃す可能性がある。 | 例外が発生することを期待する場合は、`pytest.raises` 等を使用する。 |
