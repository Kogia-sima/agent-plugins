# レビューレポート テンプレート

レポートは著者の作業リストになる。だから **上から順に対応すれば品質が上がる** 並びにし、各指摘は「どこを・どう直すか」まで書く。

## 全体ルール

- **推奨事項（第3章）が本体**。他のセクションはその補助
- 指摘 ID は `P0-1` `P1-2` のように優先度＋連番。ユーザとの議論で参照するため必ず付ける
- 該当箇所は位置情報つきで書く（`p.4 第3章 2段落目` `スライド7` `集計!B12` `¶34`）
- 引用は指摘の特定に必要な最小限に。原文を丸ごと再掲しない
- 指摘のないレイヤーは「特筆すべき問題なし」と書く。無理に絞り出さない
- 著者の能力ではなく、文書について書く
- P3 のように実害がない指摘では、「問題」欄は「なし（読みやすさの向上余地）」と正直に書く。無理に問題らしく仕立てると、優先度の信頼性が崩れる
- 第4章の観点別所見では、各レイヤーの末尾に関連する指摘 ID を `→ P0-1, P1-3` の形で並べる。読者が詳細へ辿れるようにするため

---

## テンプレート

```markdown
# レビューレポート: <文書名>

## 1. レビュー概要

| 項目 | 内容 |
|------|------|
| 対象文書 | <ファイル名>（<形式>、<分量: NNページ / NNスライド / 約NN,NNN字>） |
| レビュー日 | YYYY-MM-DD |
| 想定した目的 | <フェーズ1で特定した目的> |
| 想定した読者 | <フェーズ1で特定した読者> |
| 文書種別 | <提案書 / 設計書 / ...> |
| 前提 | <確認せずに置いた前提があれば明記。なければ「特になし」> |

**指摘件数**

| 優先度 | 件数 | 概要 |
|--------|------|------|
| P0 致命的 | N | <ひとことで> |
| P1 重要 | N | <ひとことで> |
| P2 改善推奨 | N | <ひとことで> |
| P3 任意 | N | <ひとことで> |

## 2. 総評

<3〜6文程度。この文書が現状どの水準にあり、目的を果たすために何が最大の課題かを述べる。
「読者が判断できる状態か」という観点で書くと的が絞れる。>

**良い点**

- **<どこが>**: <なぜ良いか。改稿時に壊さないでほしい理由も添える>
- **<どこが>**: <...>

## 3. 推奨事項（優先度順）

### P0-1. <指摘を一言で表すタイトル>

| 項目 | 内容 |
|------|------|
| **該当箇所** | <位置情報> |
| **現状** | <どう書かれているか。必要なら短く引用> |
| **問題** | <何が問題で、放置するとどうなるか> |
| **推奨** | <どう直すか。可能なら修正文案そのもの> |
| **観点** | L<N> <レイヤー名> |

### P1-1. <タイトル>

（同じ形式で続ける。P0 → P1 → P2 → P3 の順に並べる）

## 4. 観点別レビュー結果

### L1 目的適合性
<所見。関連する指摘 ID を参照する（例: 「→ P0-1, P1-3」）>

### L2 全体構成
<所見>

### L3 内容の妥当性
<所見>

### L4 記述・表現
<所見>

### L5 表記・体裁
<所見。誤字脱字の詳細は第5章へ>

## 5. 表記・誤字脱字の指摘一覧

一括修正用。優先度は原則 P2 だが、固有名詞・金額・日付の誤りは第3章にも掲載している。

| # | 箇所 | 現状 | 修正案 | 種別 |
|---|------|------|--------|------|
| 1 | p.2 ¶5 | 対応を検討たします | 対応を検討いたします | 脱字 |
| 2 | p.4 表2 | サーバー / p.6 サーバ | いずれかに統一 | 表記ゆれ |

## 6. 要確認事項

文書内の情報だけでは正誤を判断できず、著者または関係者の確認が必要な事項。

| # | 箇所 | 確認したいこと | なぜ確認が必要か |
|---|------|----------------|------------------|
| 1 | p.5 費用表 | 単価が最新の見積と一致しているか | 文書内に出典がなく検証できない |
```

## 記入例

実際の書きぶりの水準を示す例。**推奨の具体性**に注目すること。

### 良い例

```markdown
### P0-1. 承認を求めている内容が特定できない

| 項目 | 内容 |
|------|------|
| **該当箇所** | 全体（特に p.1 「はじめに」、p.8 「まとめ」） |
| **現状** | 「本件についてご検討をお願いいたします」で締めくくられており、承認を求める対象・金額・期限が本文中に散在している |
| **問題** | 決裁者が何に対して承認印を押すのか判断できない。差し戻しか、意図と異なる範囲での承認につながる |
| **推奨** | p.1 冒頭に「ご承認いただきたい事項」の枠を設け、「①総額 480 万円の予算執行、②2026年5月からの3か月の実施、③A部からの2名の専任」の3点を箇条書きで明示する。p.8 のまとめでも同じ3点を再掲する |
| **観点** | L1 目的適合性 |

### P1-2. 効果の記述に測定方法がなく、実施後に成否を判定できない

| 項目 | 内容 |
|------|------|
| **該当箇所** | p.5 「3.2 期待される効果」 |
| **現状** | 「会員数の増加が見込まれる」とあるが、増加幅・測定期間・測定方法の記載がない |
| **問題** | 決裁者は投資に見合う効果か判断できず、実施後も成功・失敗を誰も判定できない |
| **推奨** | 「施策開始から6か月後の新規会員登録数を、前年同期比で15%増（月次 1,200 件 → 1,380 件）とする。測定は会員管理システムの月次登録数レポートによる」のように、目標値・期間・測定手段の3点を書く。根拠となる試算があれば付録に置く |
| **観点** | L1 目的適合性 / L3 内容の妥当性 |
```

### 避けるべき例

```markdown
### P1-2. 効果の記述が不十分

- 効果についてもう少し具体的に書いたほうがよいです。
- 全体的に構成を整理すると読みやすくなると思います。
```

**なぜ避けるか**: 箇所が特定できない。「不十分」の基準が示されていない。著者が何をすればよいか分からないため、レポートを受け取っても作業が始まらない。

## 分量の目安

厳密な規定ではないが、迷ったときの基準として。

| 対象文書 | 推奨事項の件数 | レポート分量 |
|---------|--------------|-------------|
| 1〜5ページ | 3〜10件 | 1〜3ページ相当 |
| 10〜30ページ | 10〜25件 | 3〜8ページ相当 |
| 50ページ以上 | 15〜40件（統合して整理） | 8ページ相当以上 |

件数を増やすこと自体が目的ではない。**同じ原因の指摘は統合し、代表例に「他 N 箇所で同様」と添える**ほうが、著者にとって対応しやすい。逆に、誤字脱字のような機械的な指摘は第5章に全件並べる。
