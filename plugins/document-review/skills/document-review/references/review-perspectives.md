# レビュー観点カタログ

L1（最も抽象）から L5（最も具象）へ向かう5層のチェックリスト。

**使い方**: すべての項目を機械的に埋めるためのものではなく、**見落としを防ぐための網棚**として使う。文書の種別・目的によって効く観点は変わるので、当てはまらない項目は飛ばしてよい。ただし「飛ばした」と「見ていない」は違うので、各レイヤーには必ず一度は意識を向けること。

## L1 目的適合性

**中心的な問い**: この文書は、想定読者に対して目的を果たすか。

指摘が出れば最も価値が高い層だが、文書を眺めているだけでは見えにくい。**読者の立場に立って「で、自分は何をすればいいのか」と問う**と浮かび上がる。

### 目的との整合

- 文書の目的が、冒頭で読者に伝わるか。読み進めないと分からない状態になっていないか
- 目的に対して**不要な情報**が多くを占めていないか（書き手が調べたことを全部載せている、など）
- 目的に対して**決定的に足りない情報**はないか。承認を求める文書なのに判断材料（費用・リスク・代替案）がない、など
- 読者に求めるアクションが明示されているか。「ご確認ください」で終わっていて、何をどう判断すればよいか分からなくなっていないか
- タイトルと中身が一致しているか

### 読者との整合

- 想定読者の前提知識に対し、専門用語・略語・社内用語が説明なしで使われていないか
- 逆に、前提知識のある読者に対して初歩的な説明が冗長に入っていないか
- 読者の関心事（経営層なら投資対効果とリスク、実務者なら手順と例外処理）に答えているか
- 読者が抱くであろう**反論・疑問**が想定され、答えられているか
- 社外向けの場合、社内でしか通じない表現・機密情報・内部の生々しい経緯が残っていないか

### スコープ

- 扱う範囲と扱わない範囲が明示されているか。曖昧だと読者は「書いてない＝対象外」と誤解する
- 1つの文書に複数の目的が詰め込まれ、どれも中途半端になっていないか
- 他文書に委ねるべき内容を抱え込んでいないか、逆に参照先が示されずに宙に浮いていないか

## L2 全体構成

**中心的な問い**: 章立ては読者の思考の順序に沿っているか。

### 構造

- 見出しだけを並べたとき、それだけで文書の筋が追えるか
- 見出しが内容を表しているか。「その他」「補足」のような中身の分からない見出しが重要な情報を隠していないか
- 章の**粒度が揃っている**か。1章が20ページで2章が3行、のような不均衡はないか
- 階層の深さは適切か。4階層以上が続くと読者は現在地を見失う
- 導入（背景・目的）と結論が、文書の型に対して適切な位置にあるか。意思決定者向け文書なら結論が先にあるか

### 順序

- 前提となる情報が、それを使う説明より**前**に置かれているか
- 時系列・因果・重要度のどれで並んでいるか一貫しているか。途中で基準が変わっていないか
- 読者が「なぜこの話が今出てくるのか」と感じる飛躍がないか

### 過不足

- 同じ内容が複数箇所で繰り返されていないか。意図的な再掲なら、そう分かる形になっているか
- 章として存在すべきなのに欠けているものはないか（後述の「書かれていないことを探す」を参照）
- 付録に回すべき詳細が本文を圧迫していないか、逆に本文にあるべき要点が付録に埋もれていないか

### ナビゲーション

- 分量に対して目次・章番号・要約が備わっているか
- 相互参照（「詳細は第4章参照」）が機能しているか。参照先の章番号がずれていないか
- 長文の場合、各章の冒頭または末尾に要点が置かれているか

## L3 内容の妥当性

**中心的な問い**: 主張は根拠に支えられ、文書内で矛盾していないか。

このレイヤーは**突き合わせ作業**が中心になる。記憶に頼らず、抽出テキストを検索して実際に確認すること。

### 主張と根拠

- 主張に根拠が付いているか。「効果が見込まれる」の根拠は何か
- 根拠が主張を支えるのに**十分**か。1事例から一般論を導いていないか
- 出典が示されているか。数値・引用・外部情報に出典がないものは要確認に分類する
- 推測・仮定・事実が**区別して書かれている**か。仮定が事実のように書かれていないか
- 反対意見・リスク・制約が扱われているか。良い面だけが並んでいないか

### 論理

- 因果関係と相関が混同されていないか
- 「AだからB」の間に飛躍がないか。間の前提が省略されていないか
- 選択肢を比較している箇所で、比較の軸が揃っているか。一方だけ有利な軸で評価していないか
- 結論が本文の議論から導かれているか。結論だけが独り歩きしていないか

### 整合性（文書内の突き合わせ）

- **数値**: 合計と内訳が一致するか。同じ指標が別の箇所で違う値になっていないか。単位・通貨・期間の定義が揃っているか
- **日付・期間**: スケジュールの前後関係に矛盾はないか。開始前に終了する工程などがないか
- **固有名詞**: 人名・組織名・製品名・システム名が文書内で一貫しているか
- **図表と本文**: 図表が示す内容と本文の記述が一致するか。図表番号と参照が対応しているか
- **用語の定義**: 定義した用語が定義どおりに使われ続けているか

### 実行可能性（計画・手順を含む文書の場合）

- 書かれた手順・計画が実際に実行できるか。前提条件・必要な権限・所要時間が抜けていないか
- 責任者・期限・完了条件が特定されているか。「関係者で対応する」は誰も対応しない
- 例外・失敗時の扱いが書かれているか

## L4 記述・表現

**中心的な問い**: 一読して、著者の意図どおりに意味が取れるか。

### 明確さ

- **曖昧語**: 「適切に」「必要に応じて」「なるべく早く」「基本的に」「等」のように、読者ごとに解釈が分かれる語が判断を要する箇所で使われていないか
- **主語の欠落**: 誰が実行するのか特定できるか。日本語は主語を省けるので、責任の所在が消えやすい
- **係り受けの曖昧さ**: 修飾関係が複数に読める文がないか
- **多義的な指示語**: 「これ」「それ」「同様に」が何を指すか一意に定まるか
- **二重否定・過度な受動態**: 意味の取りにくい構文になっていないか
- **数量の曖昧さ**: 「大幅に増加」ではなく具体的な数値が必要な箇所ではないか

### 簡潔さ

- 一文が長すぎないか（目安として日本語で 60〜80 字を超えたら分割を検討する）
- 同じことを言い換えて繰り返していないか
- 意味を持たない前置き（「ご存じのとおり」「言うまでもなく」）が続いていないか
- 名詞の連続や過度な漢語で、読み下しにくくなっていないか

### 一貫性

- **用語**: 同じ対象を指す語が統一されているか（「ユーザ」「利用者」「顧客」の混在など）
- **文体**: 常体／敬体、です・ます／である が混在していないか
- **箇条書きの形式**: 体言止めと文末が揃っているか。項目の粒度が揃っているか
- **見出しの命名**: 体言止め・動詞形が揃っているか
- **人称・立場**: 「弊社」「当社」「我々」が揃っているか

### トーン

- 想定読者・場面に対して、丁寧さの水準が適切か（社外向けに砕けすぎ、社内向けに堅すぎ）
- 断定が強すぎないか、逆に曖昧にしすぎて主張が消えていないか
- 特定の人・部署への非難と読める表現が残っていないか
- 差別的・排他的と受け取られうる表現、不用意なジェンダー表現がないか

### 読みやすさ

- 段落が適切に分かれているか。1段落が長大になっていないか
- 箇条書き・表・図にしたほうが伝わる情報が、散文で書かれていないか（逆に、箇条書きばかりで論理の接続が失われていないか）
- 強調が乱用されて、どこが重要か分からなくなっていないか

## L5 表記・体裁

**中心的な問い**: 細部の乱れが、文書の信頼性を損なっていないか。

このレイヤーの指摘は個々の重要度は低いが、**社名・人名・金額・日付の誤り**と**意味が反転する誤変換**は例外的に重大なので、見つけたら優先度を引き上げる。

### 誤字・脱字・変換

- 誤変換（同音異義語の取り違え）
- 脱字・衍字（余分な文字）、助詞の重複や欠落
- 送り仮名の誤り
- 文の途中で終わっている、接続が壊れている箇所
- コピー＆ペーストの痕跡（別案件の名称、前バージョンの日付、重複した段落）

### 表記ゆれ

- 英数字の全角・半角
- カタカナ語の長音（「サーバ／サーバー」「ユーザ／ユーザー」）
- 漢字とひらがなの使い分け（「下さい／ください」「出来る／できる」）
- 数字の桁区切り、単位の表記（「万円／百万円」「％／パーセント」）
- 日付の形式（「2026/4/1」「2026年4月1日」「R8.4.1」）
- 英語表記の揺れ（大文字小文字、スペース有無）

### 書式・体裁

- フォント・文字サイズ・色の不統一
- インデント、箇条書きの記号、行間の乱れ
- 見出しの書式が階層と対応しているか
- 空白ページ、不自然な改ページ、表や図が途中で分断されていないか
- ヘッダ・フッタ、ページ番号の有無と連続性

### 図表

- 図表番号の連番に飛びや重複がないか
- キャプションが付いているか。キャプションだけで内容が分かるか
- 軸ラベル・凡例・単位・出典が示されているか
- グラフの表現が誤解を招かないか（軸の起点、スケール、不適切なグラフ種別）
- 本文からの参照があるか。参照されない図表が浮いていないか

### 参照・リンク

- 外部リンクが有効か（確認できる場合）、リンク先が意図した文書か
- 参照文献・出典の書式が統一されているか
- 社内文書へのパス・URL が読者からアクセス可能か

### 形式固有の確認

| 形式 | 追加で見る点 |
|------|-------------|
| **Word** | 未解決コメント、残存する変更履歴、スタイルの不統一、自動目次の未更新、隠し文字 |
| **PowerPoint** | 1スライドの情報量、文字のはみ出し・重なり、スライド番号、発表者ノートの残骸、アニメーションの過剰さ、テンプレート外の装飾 |
| **Excel** | 数式エラー（#REF! #DIV/0! など）、ハードコードされた値、参照範囲のずれ、非表示シート・行列に残る情報、条件付き書式の破綻、フィルタの掛かりっぱなし |
| **PDF** | しおり・目次の有無、フォント埋め込み、テキスト選択の可否、印刷時のレイアウト崩れ |
| **Markdown** | コードブロックの言語指定、リンク記法の崩れ、見出しレベルの飛び（h2 の次が h4）、テーブル記法の列数不一致、相対パスの妥当性 |

### 機密・コンプライアンス

- 社外向け文書に、社内限定情報・個人情報・未公開情報が残っていないか
- 秘密区分の表示が必要なら付いているか
- 第三者の著作物・商標・画像の利用が適切に扱われているか

## 横断: 書かれていないことを探す

**最も見落とされやすいのは、書かれていないもの**である。書かれている文を読んでいるだけでは絶対に見つからないので、意識的に探す。

探し方は「読者になりきって疑問を出す」ことに尽きる。想定読者の立場で以下を問う。

- この文書を読んで**まだ分からないこと**は何か。それは読者が知る必要のあることか
- 判断を求められているなら、**判断に必要な材料**は揃っているか（費用、期間、リスク、代替案、やらない場合どうなるか）
- 作業を求められているなら、**作業に必要な情報**は揃っているか（前提条件、必要な権限、失敗時の対応、完了の判定基準）
- 都合の悪い情報が省かれていないか（失敗事例、制約、未解決の課題、反対意見）
- 「次に何が起きるのか」が書かれているか（この後のプロセス、誰がいつ何を決めるのか）

見つけた欠落は、L1 または L3 の指摘として扱い、優先度は高めに見積もる。**あるものの粗より、ないものの穴のほうが読者を困らせる。**
